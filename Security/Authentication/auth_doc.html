RvCarbonApi 1.0.0 OAS 3.0

[ Base URL: http://localhost:8080 ]

Documentação oficial da API RvCarbon.
Este documento detalha os endpoints de Segurança e Autenticação, incluindo contratos de dados (DTOs) e regras de negócio da camada de Service.

Termos de Serviço | Contato Suporte
Auth Controller Autenticação e Gestão de Contas
POST /api/auth/login/ Login e emissão de JWT
Service Logic (AuthService):
  • Autentica via AuthenticationManager.
  • Gera par de tokens (Access + Refresh).
  • Regra de Bloqueio: Se o usuário não estiver ativado (email não confirmado), lança DisabledException.
Request Body
{ "loginIdentifier": "user@rvcarbon.com", // Email ou Username "password": "Senh@Forte123" // Min 6 caracteres }
Responses
CodeDescription
200 Sucesso. Retorna Token Pair.
Schema: JwtTokenPair
401 Credenciais inválidas (BadCredentials).
403 Conta inativa/não verificada. Verifique seu email.
POST /api/auth/register/ Cadastro de novo usuário
Service Logic: Ao registrar, o status do usuário é definido como inativo. Um token de ativação (tipo ACTIVATION) é gerado e enviado por e-mail.
Request Body (AuthRegisterRequest)
{ "name": "João Silva", "email": "joao@email.com", "phone": "(11) 99999-9999", // Pattern: (xx) xxxxx-xxxx "username": "joaosilva", // Min 3, Max 30 "password": "secret123", // Min 6 chars "birthday": "1990-01-01", // Deve ser passado "state": "SP", "city": "São Paulo", "cpfCnpj": "123.456.789-00", // Validação rigorosa de formato "occupation": "Agrônomo", "academicTitle": "Doutor", "imageProfileUrl": "http://..." }
Responses
200 Usuário registrado com sucesso. Retorna AuthRegisterResponse.
400 Erro de validação (Campos inválidos ou padrão incorreto).
POST /api/auth/refresh/ Renova o Access Token
Security Logic:
  • Verifica se o token é do tipo REFRESH.
  • Valida se o token está na Blacklist ou Expirado.
  • Se válido: invalida o token atual (Blacklist) e gera um novo par.
Request Body
{ "refreshToken": "eyJhbGciOiJIUzI1NiJ..." }
Responses
200Novo par de tokens gerado.
401Refresh token inválido, expirado ou blacklisted.

PATCH /api/auth/me/ Atualizar Perfil
Request Body (AuthUpdateRequest)
{ // Campos são opcionais. Envie apenas o que deseja alterar. "name": "Novo Nome", "phone": "(11) 99999-8888" }
Responses
200Perfil atualizado. Retorna dados atualizados.
DELETE /api/auth/me/ Solicitar Exclusão de Conta
Critical Business Logic:
  • O sistema verifica se o usuário possui Fazendas (Farm Owner).
  • Se possuir fazendas: Lança DeleteUserException (Erro de Negócio). A exclusão é impedida.
  • Se não possuir: Envia e-mail de confirmação (Token type: ACCOUNT_DELETION).
Responses
204Solicitação aceita. Email enviado.
403Erro: Usuário possui fazendas vinculadas.
Fluxos de Email (Reset Senha / Confirmação)
POST /api/auth/forgot-password/ Solicitar Reset de Senha
Request Body
{ "email": "user@email.com" }
Responses
200Email enviado (se usuário existir).
POST /api/auth/reset-password/ Definir Nova Senha
Business Logic: Verifica se a nova senha é exatamente igual à antiga. Se for, lança ResetPasswordException.
Request Body
{ "token": "token_recebido_no_email", "newPassword": "NovaSenh@123" }
Responses
200Senha alterada com sucesso. 400Erro: Nova senha igual à anterior ou Token inválido.
